# 架构说明

## 总览

《不喝孟婆汤》是一个 React + TypeScript 全栈网页游戏，设计上把「逻辑」「内容」「存档」「界面」四层彻底分开——这也是它能从托管环境导出为独立开源版的原因。

```
客户端 (React) ──HTTP──> 服务端动作层 ──> 纯 TS 逻辑核 ──> JSON 内容池
                              │
                              └──> SaveStorage 抽象 ──> 存储实现（托管版：数据库 / 开源版：本地存储）
```

## 逻辑核（纯 TypeScript）

- `state.ts`：全局状态与存档读写入口。
- `dice.ts` / `checks.ts`：判定表达式解析器、modifier 链、检定配置表（Q34 分系统骰子的公式集中在此）。
- `rng.ts`：种子化随机（seedrandom）。种子由「存档 ID + 世数 + 事件类型 + 操作序号」组成，同一存档同一操作序列结果可复现；PRNG 内部状态可导出 / 恢复并随存档保存。
- `reincarnation.ts`：轮回结算（评级、轮回点、记忆保留、传承点赎回）。
- `events-base.ts` 等：事件牌堆（按稀有度权重的不放回抽取）、事件模板（代价 / 循环 / 三选一 / 双解 / 道德分叉）与路线系统。

逻辑核不依赖任何界面框架与宿主环境，可直接移植到其他引擎（见路线图中的 Godot 移植计划）。

## 内容池（JSON 配置表）

全部静态内容在 `server/src/content/*.json`：80 条探索事件（按通用 / 稀有 / 地区 / 城市 / 宗门分文件）、12 个地点、12 位 NPC、28 件法宝、功法、天赋、命格、灵根、敌人，以及委托、限时帖、签到、锻造、细时钟耗时等系统配置表。

加载时有两层校验：zod 结构校验 + 跨池引用完整性自检；配置非法会在启动时直接报错，而不是运行时静默出错。改内容只改 JSON，不用动代码。

## 存档层

- `storage.ts` 定义 `SaveStorage` 异步接口（write / read / list / remove），存档对存储层是不透明的 JSON 字符串；槽位映射（游戏存档、报错记录）集中在一处。
- 托管版实现走数据库（Drizzle）；开源版替换为本地存储实现，上层代码不改。
- `savefields.ts` 是存档字段注册表：每个可持久化字段登记路径、类型与旧存档默认值，模块加载时自检（重复登记 / 父路径缺失直接抛错）。旧存档靠注册表自动补默认值迁移，格式长期稳定。
- 游戏内导出 / 导入的存档 JSON 与开源版兼容，进度可互相迁移。

## 服务端动作层

38 个已发布动作（状态读取、各类行动、斗法、社交、宗门、经济、轮回结算、存档导出导入、AI 透传等），统一走 respond 组装返回。托管版经平台桥调用，开源版改为普通 HTTP 接口，动作语义不变。

## AI 透传

设置页的 AI 连接走统一适配：云端厂商经服务端透传（API Key 只在请求中转发，服务端不落盘、不记日志），Claude 走原生 Messages API，本地模型（Ollama / LM Studio）由浏览器直连玩家本机。Key 本体只存玩家浏览器的 localStorage。

## 客户端

React 单页应用：主菜单（水墨动图题屏）、规则设定 / 只读规则页、降生创建、游戏盘五页（角色 / 地图探索 / 修炼宗门 / 社交经济 / 轮回历史）、百科、设置页。视觉为水墨宣纸设计系统（CSS 设计变量 + 主题三档：浅色 / 深色 / 跟随系统）。
